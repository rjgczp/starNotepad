# Love Cottage 微信测试号配置

情侣空间直接调用微信公众平台测试号的 `stable_token` 和模板消息接口，不依赖 ServerChan、WxPusher 或付费中间服务。测试号只适合两个人自用；微信可能调整展示方式或限制频率，站内消息和回信记录始终是最终数据来源。

## 1. 创建测试号与模板

1. 打开微信公众平台接口测试号页面并登录。
2. 让两个人分别扫描测试号二维码关注。
3. 复制测试号的 `appID`、`appsecret`，以及关注列表中两个人各自的 OpenID。
4. 新建模板，至少包含两个文本字段：

```text
{{title.DATA}}
{{content.DATA}}
```

如果字段名不是 `title`、`content`，修改 `config.yaml` 中的 `wechat-title-field` 和 `wechat-content-field`。

## 2. 配置部署环境

在 `.env.production` 中设置：

```dotenv
WX_TEST_ENABLED=true
WX_TEST_APPID=测试号_appID
WX_TEST_SECRET=测试号_appsecret
WX_TEST_TEMPLATE_ID=模板ID
DUO_PUBLIC_BASE_URL=https://ai.xiaoyu.ski
```

`DUO_PUBLIC_BASE_URL` 必须使用浏览器可访问的情侣空间 HTTPS 根地址。当前情侣空间部署在 `ai.xiaoyu.ski` 根路径，不要额外添加 `/duo`。推送链接只带 `daily:记录ID` 或 `chat:记录ID` 形式的不透明定位值，不包含聊天、回信、OpenID、AppSecret 或 access token。

修改后重启后端。管理端“爱情小屋 → 微信推送”会显示四项配置健康状态。

## 3. 绑定与测试

1. 在管理端分别为身份 1 和身份 2 粘贴 OpenID。
2. 先保持默认的“仅提醒”模式并启用绑定。
3. 分别点击“发送测试”，到“推送队列”查看 `pending`、`sent` 或 `failed` 状态。
4. 确认两个人都收到测试消息后，再按类别选择是否显示正文。

图片消息永远只发送“收到一张图片”的通用提醒，不会把图片地址发给微信。“显示内容”可能让文字出现在锁屏上，请只在双方明确接受时开启。

## 4. 密钥与 OpenID

- AppSecret 只通过部署环境注入，不写入数据库、接口响应或日志。
- OpenID 使用 `DUO_CALL_KEY_ENCRYPTION_KEY` 加密保存，管理端只显示脱敏值。
- 必须备份加密密钥；丢失后只能重新绑定 OpenID。
- 轮换密钥前先停用微信 worker，完成数据迁移或重新绑定后再启用。

## 5. 故障停用

紧急停用时将 `WX_TEST_ENABLED=false` 并重启后端。聊天、图片和每日回信仍会正常保存，只停止微信外发。

## 每日问题与提醒节奏

- 每天 `08:00`（`Asia/Shanghai`）执行一次周期任务。
- 如果上一题尚未双方回答，系统继续使用原问题，不生成新题，并只推送给尚未回答的一方。
- 未回复提醒固定在晚间 `19:00`、`20:00`、`21:30` 和 `23:00`，早上生成问题时不推送，避免白天频繁打扰。
- 某一方提交回信后，该身份立即停止提醒；双方都回答后，该问题的全部提醒停止。
- `23:00` 是当天最后一次提醒。若第二天仍有人未回答，`08:00` 会沿用原问题，并在新一天晚间重新提醒未回复身份。
- 服务在 `08:00` 前启动不会提前生成；在 `08:00` 后启动会幂等补跑一次。访问“今日问题”接口不会触发生成。
- AI 问题会轮换共同回忆、具体计划、彼此观察、生活选择、感官细节、童年经历和有趣假设等主题，并拒绝近期相似或反复使用“今天有什么小事/哪个瞬间让你暖暖的”结构的问题。

管理端“爱情小屋 → 每日回信 → 最近周期与提醒”可查看周期是否完成、每个身份的已提醒次数及下次提醒时间。

发送失败会指数退避，达到上限后进入 `failed`。管理端只显示经过清洗的错误摘要，可以修复配置后人工重试。常见问题：

- `40001`、`40014`、`42001`：token 失效，系统会自动刷新并重试一次。
- OpenID 无效或用户取消关注：重新关注并更新对应身份的 OpenID。
- 模板字段错误：确认模板字段与配置中的字段名一致。
- 长时间 `pending`：确认 `WX_TEST_ENABLED=true` 且后端已重启。
